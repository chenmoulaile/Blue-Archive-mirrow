## 蔚蓝档案同人桌面客户端 —— Phase 0 素材管线（完成）

**做了什么**：从零搭建素材与数据抓取管线，为 Electron 客户端备齐资源。

### 数据源（关键发现，后续复用）

- **kivo.wiki** 有完全开放的 JSON API：`https://api.kivo.wiki/api/v1/`
  - `data/spines/` Spine 索引 1796 条（`home` 回忆大厅 434、`spr` 立绘 1362），
    `data/spines/{id}` 给 `.skel/.atlas/.png` 直链（`static.kivo.wiki/spines/{name}/`）
  - `galleries/` 36 个相册 19237 张图；`galleries/{id}` 给 `categorys[].images[]`
  - `data/students/{id}` 含 `spine[]`、`voice[]`、`furniture[]`、`gift_data[]`、`recollection_lobby_image`
  - `timeline/?type=Gacha` 862 条卡池、`type=Event` 544 条活动
  - 无 BGM/SE 音频
- **bluearchive.wiki**（Miraheze）剧情用 `{{Story}}` 模板存，参数是「序号+节点类型+字段」，
  与节点图 JSON 天然同构。`curl` 直连 403（Cloudflare，且不依赖 cookie），
  必须 Playwright 驱动本机 Chrome 在页面上下文 `fetch()`。
- 剧情全集枚举必须用 `insource:"Story/StoryTop"`（2479 页）；
  按前缀+Category 只能拿到 945 页，羁绊正文在 `<学生>/Relationship Story/N` 子页。

### 三个硬约束（影响架构，务必记住）

1. **Spine 是 4.2.x**（4.2.33/37/40/43），`pixi-spine` 只支持到 4.1 → 必须换
   `@esotericsoftware/spine-webgl` 4.2，独立 canvas 层叠在 Pixi 上。规格书里
   「PixiJS + pixi-spine 3.8」这条作废。
2. **wiki 不记录分支拓扑**：`choice` 节点只有组号，实际选中句以 `sensei` 节点出现在后面，
   记录的是单条通关路径。
3. **BGM 311 种 / SE 834 种无公开可下载源**，播放器要做静音降级 + 用户自备音频目录。

### 坑

- 并发开 3 个 Chrome 抓 wiki 会假死且不报错，日志停更但进程还在。
  最终方案：单浏览器 + 2 页 + 硬超时 30s + 看门狗（75s 无新文件就 reload）。
- Git Bash 里 `taskkill //F //IM node.exe` 会连带杀掉其他 node 任务，注意时机。

## Phase 1–9 全量实现（完成）

**做了什么**：把 Electron 客户端从零写到能跑，8 个模块全部打通。

### 技术栈落地

Electron 38 + Vite 6 + React 18 + TS 严格模式（`strict: true`，`tsc --noEmit` 零错误）。
主进程 `electron/main.ts` 起一个 127.0.0.1 随机端口的 http 服务器，统一提供
`/res/*`（素材）、`/data/*`（JSON）、`/`（渲染层），避开 file:// 的 CORS 与 WebGL 贴图限制。

### Spine 4.2 的四个坑（详见 docs/spine-rendering.md）

1. **`drawSkeleton(sk, false)`** —— BA 的 atlas 没有 `pma: true`，传 `true` 会整片白色色块。
2. **`OrthoCamera.zoom` 是「世界单位/像素」**，`zoom = h / (vh * fit)`；
   写反会钻进贴图内部，画面是整片纯色渐变。
3. **不能用附件包围盒做自动适配** —— 道具/背景板能把包围盒撑大 3~5 倍，
   改成「包围盒完整装下 + 用户滚轮缩放/拖拽平移」，每个模型独立记忆视角。
4. **Playwright 的 `page.screenshot()` 抓不到 WebGL**，必须用
   `win.webContents.capturePage()`；同理 `canvas.toDataURL()` 读到的是清空后的缓冲。

### 环境坑

- 本机环境有 `ELECTRON_RUN_AS_NODE=1`，直接跑 electron 会退化成纯 Node
  （`require('electron')` 返回二进制路径）。`scripts/start.mjs` 里 delete 掉。
- 虚拟化环境下 GPU 进程会崩（exit_code=-1073741824 类），端到端测试要加 `--no-sandbox`。
- 单行 CSS grid 默认按内容撑高，长列表会把整页顶出屏幕 →
  `.shell { grid-template-rows: minmax(0,1fr) }` + 网格子项 `min-height: 0`。

### 用户硬性要求：不许写 C 盘

- `.npmrc` 设 `cache=E:/npm-cache`、`electron_config_cache=E:/npm-cache/electron`
- 主进程里 `app.setPath('userData'|'sessionData'|'logs'|'cache')` 全部指到
  `E:/Blue archive/.userdata`
- 已确认 `AppData/Roaming` 下没有生成应用目录。
- C 盘还剩一个 1.2G 的历史 npm 缓存（`AppData/Local/npm-cache`），是本次之前就有的，
  已告知用户可清理，未擅自删除。
